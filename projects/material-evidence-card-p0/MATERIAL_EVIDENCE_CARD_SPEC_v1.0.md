# MATERIAL_EVIDENCE_CARD_SPEC_v1.0

```text
STATUS: FROZEN_FOR_SYNTHETIC_PORTFOLIO_SERIES
SCOPE: Material Evidence Card P0 and scheduled Monday / Wednesday / Friday synthetic showcases
AUTHORITY: This file defines the shared field names, state model, display boundary, and publication gates.
SCIENTIFIC_VALIDATION_AUTHORITY: NONE
```

## 1. Purpose

This specification defines a consistent, audit-friendly interface contract for Material Evidence Card portfolio demonstrations.

It separates:

```text
COMPOSITION DESCRIPTION
ARTIFACT IDENTITY
ARTIFACT CHECKS
SCIENTIFIC VALIDATION
SCIENTIFIC CLAIMS
```

Successful parsing or rendering must never be promoted into a material-science conclusion.

## 2. Required record order

Every card and README record must present these sections in this order:

```text
1. FIXTURE_ID
2. RECIPE_CLASS
3. NOMINAL_ATOMIC_COMPOSITION
4. SOURCE_PROVENANCE
5. ARTIFACT_IDENTITY
6. ARTIFACT_CHECKS
7. SPATIAL_DISPLAY_BOUNDARY
8. SCIENTIFIC_BOUNDARY
9. DOWNLOADS_OR_FILE_PATHS
10. KNOWN_LIMITS
```

## 3. Recipe classes

Allowed values:

```text
SYNTHETIC_FIXTURE
PUBLIC_SOURCE
HYPOTHESIS_CANDIDATE
```

### 3.1 SYNTHETIC_FIXTURE

Required defaults:

```text
SOURCE_PROVENANCE.ORIGIN: GENERATED_IN_PROJECT
SCIENTIFIC_HYPOTHESIS_STATUS: NONE
SCIENTIFIC_VALIDATION: NOT_ASSESSED
SCIENTIFIC_CLAIM_STATUS: NONE
DECISION_USABLE: FALSE
```

The recurring Monday / Wednesday / Friday automation is authorized to produce only this class.

### 3.2 PUBLIC_SOURCE

A public-source record requires:

```text
SOURCE_REFERENCE
SOURCE_ACCESS_DATE
SOURCE_LICENSE_OR_REUSE_BASIS
TRANSFORMATION_HISTORY
PROJECT_VALIDATION_STATUS
```

Public visibility alone is not sufficient evidence of redistribution rights. Source-reported claims must not be restated as claims validated by this project.

### 3.3 HYPOTHESIS_CANDIDATE

A hypothesis candidate requires:

```text
RATIONALE
ASSUMPTIONS
EXPECTED_OBSERVATION
FALSIFICATION_OR_REJECTION_CONDITION
MISSING_VALIDATION
DECISION_USABLE: FALSE
```

It requires explicit human authorization and is not generated by the recurring synthetic-fixture automation.

## 4. Composition model

The authoritative field name is:

```text
NOMINAL_ATOMIC_COMPOSITION
```

For the current synthetic series:

```text
BASIS: ATOMIC_PERCENT
DERIVATION: DISPLAY_ATOM_COUNT
```

Each component must record:

```json
{
  "display_atom_count": 8,
  "atomic_percent": 50.0
}
```

The manifest must also record:

```text
TOTAL_ATOMIC_PERCENT
TOLERANCE
DISPLAY_NOTATION
```

Publication requires:

```text
ABS(TOTAL_ATOMIC_PERCENT - 100) <= TOLERANCE
```

The UI may show compact notation such as `Fe50Ni25Cr25 (at.%)`, but compact notation is not the authority. The per-element values, basis, and derivation in the manifest are authoritative.

The following labels are prohibited when only synthetic display atoms exist:

```text
VALIDATED_ALLOY_FORMULATION
OPTIMIZED_RECIPE
RECOMMENDED_COMPOSITION
PROVEN_PHASE
```

## 5. Spatial display boundary

For XYZ / Cartesian-only fixtures:

```text
COORDINATE_BASIS: CARTESIAN_ONLY
CRYSTALLOGRAPHIC_SEMANTICS: NONE
DISPLAY_BOUNDS_ROLE: VISUAL_AID_ONLY
DISPLAY_BOUNDS_IS_UNIT_CELL: FALSE
```

The visible label must state:

```text
CARTESIAN DISPLAY BOUNDS
VISUAL AID — NOT A UNIT CELL
```

Crystal directions such as `[100]`, `[110]`, and `[111]`, and conventional / primitive cell labels, are prohibited unless lattice vectors, coordinate basis, periodic semantics, provenance, and transformation history are provided and validated.

## 6. Artifact-check state model

Allowed status values:

```text
NOT_RUN
PASS
FAIL
UNAVAILABLE
```

Definitions:

- `NOT_RUN`: the check was not executed.
- `PASS`: the check was executed and met its recorded acceptance condition.
- `FAIL`: the check was executed and did not meet its acceptance condition.
- `UNAVAILABLE`: the check could not be executed in the release environment.

The UI checkmark `✓` represents only `PASS`.

Boolean `true / false` must not replace this state model because `false` cannot distinguish not run, failure, and unavailable.

Required checks for recurring synthetic releases:

```text
PARSE
HASH_VERIFICATION
COMPOSITION_DERIVATION
MANIFEST_UI_IDENTITY
JAVASCRIPT_SYNTAX
RENDER_REPLAY
```

`RENDER_REPLAY` means the same input, viewer build, recorded camera preset, and representation can recreate the semantic view. It does not promise cross-browser or cross-GPU pixel identity.

## 7. Scientific boundary

Synthetic portfolio defaults:

```text
SCIENTIFIC_HYPOTHESIS_STATUS: NONE
SCIENTIFIC_VALIDATION: NOT_ASSESSED
SCIENTIFIC_CLAIM_STATUS: NONE
DECISION_USABLE: FALSE
```

`NOT_ASSESSED` means phase stability, performance, processing, manufacturability, and experimental validation were not performed.

`NONE` means the project makes no scientific conclusion or material recommendation for the fixture.

## 8. Identity and provenance

Every released fixture must include:

```text
FIXTURE_ID
STRUCTURE_FILE
STRUCTURE_SHA256
ATOM_COUNT
RECIPE_CLASS
SOURCE_PROVENANCE
SPECIFICATION_VERSION
```

Fixture IDs must be sequential and immutable after publication. Existing fixture files and hashes must not be silently replaced.

## 9. Recurring publication gate

A Monday / Wednesday / Friday synthetic update may be published only when:

```text
SEQUENTIAL_FIXTURE_ID: PASS
PREVIOUS_FIXTURES_PRESERVED: PASS
RECIPE_CLASS: SYNTHETIC_FIXTURE
ATOMIC_PERCENT_BASIS_PRESENT: PASS
COMPOSITION_SUM_CHECK: PASS
XYZ_PARSE: PASS
SHA256_BINDING: PASS
MANIFEST_UI_IDENTITY: PASS
JAVASCRIPT_SYNTAX: PASS
SCIENTIFIC_VALIDATION: NOT_ASSESSED
SCIENTIFIC_CLAIM_STATUS: NONE
DECISION_USABLE: FALSE
```

If a required deterministic check is `FAIL`, the release must not be merged.

If render replay is `NOT_RUN` or `UNAVAILABLE`, that status must be displayed honestly and must not be converted to `PASS`.

## 10. Change control

This v1.0 specification is frozen for the current synthetic portfolio series.

A change to field names, status meanings, recipe classes, scientific boundaries, or release gates requires:

```text
NEW_SPEC_VERSION
MIGRATION_NOTE
AFFECTED_FIXTURE_LIST
HUMAN_APPROVAL
```

A new recipe does not itself justify changing this specification.
